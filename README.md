# LocalDocumentSearchPWA

LocalDocumentSearchPWAは、iPhone Safariからファイルを選択して登録し、抽出した本文をブラウザ内のIndexedDBに保存して横断検索するPWAです。Mac、Xcode、Apple Developer Program、App Store配布、TestFlight配布は使いません。

資料本文は外部サーバーへ送信しません。GitHub Pagesにはアプリ本体だけを配置し、ユーザーが登録したPDF、Excel、Word、CSVなどの資料データは各端末のブラウザ保存領域に残ります。

## MacなしでiPhoneに入れて使う考え方

このアプリはネイティブiOSアプリではなく、Safariからホーム画面に追加して使うPWAです。GitHub Pagesで公開したURLをiPhone Safariで開き、「ホーム画面に追加」することで、ホーム画面からアプリのように起動できます。

PWAでは、iPhone内の任意フォルダを常時監視したり、ユーザー操作なしで元ファイルを自動的に読み直したりすることはできません。このMVPでは、ユーザーがファイル選択画面から選んだ資料を読み込み、抽出済み本文をIndexedDBへ保存します。

## iPhoneホーム画面に追加する方法

1. GitHub Pagesで公開したアプリURLをiPhone Safariで開きます。
2. Safariの共有ボタンを押します。
3. 「ホーム画面に追加」を選びます。
4. 名前が「LocalDocumentSearchPWA」になっていることを確認して追加します。
5. ホーム画面のアイコンから起動します。

Service Workerにより、アプリ本体はキャッシュされ、オフラインでも起動できます。ただし、初回表示やライブラリ取得にはオンライン接続が必要です。

## ローカル開発環境での起動方法

このアプリの開発とビルドにはNode.js LTS版が必要です。Windowsでは、Node.js公式サイトからLTS版をインストールしてからPowerShellまたはコマンドプロンプトを開き直してください。

まず、Node.jsとnpmが使えることを確認します。

```bash
node -v
npm -v
```

どちらかが「認識されません」と表示される場合は、Node.js LTS版がインストールされていないか、PATHが反映されていません。Node.jsを再インストールするか、`C:\Program Files\nodejs\` がPATHに含まれていることを確認し、ターミナルを開き直してください。

PowerShellで`npm.ps1`の実行が制限される場合は、次のように`npm.cmd`を使って実行できます。

```bash
npm.cmd install
npm.cmd run build
npm.cmd run dev
```

通常は次の手順で起動できます。

```bash
npm install
npm run dev
```

表示されたURL、通常は`http://localhost:5173/`または`http://127.0.0.1:5173/`をPCブラウザで開いて確認してください。

ビルド確認:

```bash
npm run build
npm run preview
```

可能であれば型チェックも実行してください。

```bash
npm run lint
npm run test
```

### Codex実行環境での検証メモ

この作成時点のCodex実行環境では、通常のPATH上で`npm`が見つからず、`node`もCodexアプリ内の実行ファイルを指してアクセス拒否になりました。そのため、検証時は`work`配下にポータブル版Node.jsを配置し、その中の`npm`で`npm install`、`npm run build`、`npm run dev`を実行しました。

ユーザーのWindows環境で実行する場合は、上記のとおりNode.js LTS版を通常インストールし、`node -v`と`npm -v`で確認してから`npm install`を実行してください。`work`配下のポータブルNode.jsは検証用の一時ファイルであり、GitHub Pages公開や通常利用には不要です。

## GitHub Pagesへの公開方法

このリポジトリにはGitHub Actions用の`.github/workflows/deploy.yml`を含めています。

1. GitHubへリポジトリをpushします。
2. GitHubの設定画面でPagesを開き、公開方法を「GitHub Actions」にします。
3. `main`ブランチへpushするか、Actions画面から手動実行します。
4. `npm install`、`npm run build`が実行され、`dist`がGitHub Pagesへ公開されます。

Viteの`base`はnpm scriptsのCLI引数で`./`に設定し、ルーティングはHashRouterを使っているため、リポジトリ名付きのGitHub Pages URLでも動作しやすい構成です。

## ファイルの登録方法

1. アプリの「ファイル登録画面」を開きます。
2. 「ファイルを選択」を押します。
3. iPhone内、iCloud Drive、Google Driveなど、iOSのファイル選択画面に表示される場所から資料を選びます。
4. 複数ファイルをまとめて選択できます。
5. ファイル形式ごとに本文を抽出し、IndexedDBに保存します。
6. 登録後は「資料一覧画面」と「検索画面」から確認できます。

途中で1つのファイル処理に失敗しても、他のファイルの登録処理は継続します。

## iPhone内ファイルの登録方法

ファイルアプリの「このiPhone内」に保存されているPDF、Excel、Word、CSV、TXTなどを選択してください。選択されたファイルだけがアプリに読み込まれます。

## iCloud Drive上のファイルの登録方法

iOSのファイル選択画面で「iCloud Drive」を選び、登録したい資料を選択してください。登録後は抽出済み本文がIndexedDBに保存されます。元ファイルが更新された場合は、再度ファイルを選択して登録し直してください。

## Google Drive上のファイルを登録する方法

MVPではGoogle Drive APIを使いません。次の方式で登録してください。

1. iPhoneにGoogle Driveアプリを入れます。
2. iOSのファイルアプリでGoogle Driveを参照できる状態にします。
3. PWAの「ファイル登録画面」でファイル選択を開きます。
4. Google Drive上のPDF、Excel、Word、CSVなどを選択します。
5. 選択されたファイルをPWAが読み込み、抽出本文をIndexedDBに保存します。

Google Drive上のファイル更新は自動反映されません。必要に応じて再登録してください。

## 対応ファイル形式

- PDF: `.pdf`
- テキスト: `.txt`
- マークダウン: `.md`, `.markdown`
- CSV: `.csv`
- TSV: `.tsv`
- Excel: `.xlsx`, `.xlsm`, `.xls`
- Word: `.docx`
- HTML: `.html`, `.htm`
- JSON: `.json`

MVPで重点確認する形式は、PDF、テキスト、マークダウン、CSV、表計算 `.xlsx`、Word文書 `.docx`です。古いWord形式の`.doc`はMVP対象外です。必要に応じてWordやGoogle Docsなどで`.docx`へ変換してから登録してください。

## ファイル形式ごとの抽出精度

抽出精度はファイル形式と内容により異なります。検索対象にするのは本文テキストであり、レイアウト、罫線、色、フォント、グラフ、画像などの完全再現は目的にしていません。

## PDFの注意点

PDF.jsでページ単位のテキストを抽出します。検索結果にはページ番号を表示します。

スキャンPDFや画像だけのPDFは、OCR機能がないため検索対象にできません。また、2段組PDFや表中心のPDFでは、抽出順序が見た目と異なる場合があります。

## Excelの注意点

SheetJSでブック内の全シートを読み込み、セルの表示値を検索対象にします。検索結果には、ファイル名、シート名、行番号、セル範囲を表示します。

Excelの罫線、色、フォント、グラフ、画像は検索対象外です。数式が取得できる場合はメタデータに保存します。

## CSV / TSVの注意点

Papa ParseでCSVとTSVを読み込みます。ヘッダー行があると推定できる場合は、列名も検索対象に含めます。文字コードや区切り文字の違いにより読み込みに失敗する場合があります。

## Wordの注意点

Mammoth.jsで`.docx`の見出し、段落、表内テキストを抽出します。レイアウトの完全再現は目的にしていません。`.doc`はMVP対象外です。

## テキスト / マークダウンの注意点

テキストとマークダウンは文字情報として読み込みます。長文は一定文字数でチャンク化します。マークダウンは見出し情報を可能な範囲でメタデータとして保存します。

## HTML / JSONの注意点

HTMLは`script`、`style`、`meta`などを除外し、本文テキストを抽出します。JSONはインデント付き文字列に整形し、キーと値の両方を検索対象にします。

## 登録済み資料の検索方法

1. 「検索画面」を開きます。
2. 検索キーワードを入力します。
3. 必要に応じてファイル形式やファイル名で絞り込みます。
4. 「資料を検索」を押します。

大文字小文字は区別しません。複数キーワードを入力した場合は、空白で区切られた語句を検索します。

検索結果では、原則として一致語句の前後100文字程度を表示します。検索語句はハイライト表示されます。HTMLとして直接埋め込まず、Reactの通常描画でエスケープされるため、登録資料内にHTML文字列が含まれていてもそのまま実行されません。

現在のチャンクだけでは前後100文字を取得できない場合、同じ資料内の前後チャンクを参照して、可能な範囲で文脈を補います。

## 検索結果に表示される根拠情報

- PDF: ファイル名、ページ番号、該当箇所
- Excel: ファイル名、シート名、行番号、セル範囲、該当箇所
- CSV / TSV: ファイル名、行番号、該当箇所
- Word: ファイル名、見出しまたは段落情報、該当箇所
- テキスト / マークダウン: ファイル名、見出しまたはチャンク番号、該当箇所

検索結果をタップすると「資料詳細画面」に移動し、該当チャンクを確認できます。

## 登録済み資料の削除方法

資料一覧画面で各資料の削除ボタンを押すと、資料単位で削除できます。設定画面では「すべての資料を削除」を実行できます。削除操作では確認ダイアログを表示します。

検索履歴は設定画面の「検索履歴を削除」から削除できます。検索インデックスは「検索インデックスを再作成」から再構築できます。

## IndexedDBに保存されるデータ

IndexedDBには次のデータを保存します。

- DocumentRecord: ファイル名、形式、サイズ、登録日、チャンク数、メタデータ
- ExtractedChunk: チャンク本文、ページ番号、シート名、行番号、セル範囲、見出し、位置情報
- SearchIndex: 検索用に正規化したチャンク本文
- ImportHistory: 登録処理の成功・失敗履歴
- AppSettings: 検索結果の前後表示文字数などの設定

登録資料はファイル全体を1つの巨大な本文として保存せず、検索しやすいチャンク単位で保存します。

## 外部送信しない設計

このMVPでは、資料本文を外部サーバーへ送信しません。ChatGPT API、OpenAI API、Gemini API、Firebase、サーバー側DBは使用していません。

ネットワークリクエストは、アプリ本体の配信、ライブラリの読み込み、GitHub Pages配信に必要なものに限定する設計です。実資料はリポジトリに含めないでください。`public/samples`には動作確認用のサンプル資料だけを含めています。

## ブラウザ保存領域に関する注意

登録した資料データはブラウザ内のIndexedDBに保存されます。ブラウザのデータ削除、端末容量不足、Safariの仕様変更、長期間未使用などにより、保存データが消える可能性があります。

重要な元ファイルは削除せず、iPhone内、iCloud Drive、Google Driveなどに保管してください。このPWA内のデータはバックアップではありません。

## Google Drive APIを使った将来拡張方針

将来、Google Drive API / Google Picker APIを使えば、Googleドライブ内のファイルを直接選択・取得できます。その場合は次の準備が必要です。

- Google Cloudプロジェクト
- OAuthクライアントID
- Google Drive APIのスコープ設定
- Googleドライブへのオンラインアクセス
- Drive上のファイル更新日時を確認し、必要に応じて再取得する同期処理

Google Drive API対応版は完全オフラインではありません。まずは、iOSのファイル選択画面経由でGoogle Driveファイルを登録する方式を推奨します。

## ローカルLLMやAI回答機能について

このMVPの目的は、AI回答ではなく、ローカル資料を安全に登録し、横断検索し、根拠箇所を素早く見つけることです。ローカルLLM、AI回答、ベクトル検索、セマンティック検索はMVP対象外です。
